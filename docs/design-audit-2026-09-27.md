# Cookly design audit — 2026-09-27

## Scope and evidence

**Status: D01–D12 implemented in the follow-up repair.** The findings below preserve the original observations; they are not a list of remaining defects. See the resolution log at the end for changes and repeat verification.

Reviewed the current local production build against `design-package/home.png`, `auth.png`, `profile.png`, `pantry.png`, and `admin.png`, accounting for the subsequently approved product changes.

Captured 60 screens: Home, catalog, recipe detail, Pantry preview, sign-in, sign-up, 404, public profile, owner profile with inline editor, My recipes, user recipe editor, Studio overview, Studio recipes, Studio editor, and verification. Each page was captured at 1448 px in both themes, 768 px in light mode, and 390 px in dark mode. Consumer screenshots use Russian; Studio intentionally uses English. Additional dock checks cover 1100/1448 px, keyboard focus, reduced motion, and every animation frame.

Protected pages used generated identities and recipes only in a fresh loopback PostgreSQL database named `cookly_test`. No production user data, uploads, or recipe changes were used. Audit identities and their recipe fixtures were removed after capture. Images are existing local recipe assets.

Local screenshots and the animation recording are in `test-results/design-audit-2026-09-27/` (ignored by Git). These paths are local QA artifacts, not published assets. No broken loaded images or document-level horizontal overflow were detected in the 60 captured states. This is a visual review, not a complete accessibility certification or a production deployment check.

## Fixed in this change

Desktop dock rows now retain the same 196 px layout, 52 px height, 44 px icon track, padding, and grid in both states. Only the shell width, row clipping, and label opacity/translation change. Language and account popovers remain outside row clipping. The collapse no longer changes the panel height and therefore no longer shifts its vertically centered position.

The shell opens over 300 ms; existing reduced-motion rules suppress the movement. Keyboard focus has an explicit ring around the icon inside the clipped row. A regression test samples all seven guest icons throughout expansion and collapse in both themes at 1100 and 1448 px, allowing at most 0.6 px measurement variance. The signed-in audit also measured identical before/after coordinates for all seven icons, including the avatar.

Evidence: [motion recording](../test-results/design-audit-2026-09-27/dock-motion.webm), [expanded dock](../test-results/design-audit-2026-09-27/dock-expanded-light.png), and `tests/e2e/i18n-and-layers.spec.ts`.

### D12 / P2 — Excessive mobile filter height

On My recipes at 390 px, the Status filter occupies an oversized panel with blank space between its label and control. [Screenshot](../test-results/design-audit-2026-09-27/my-recipes-390-dark.png).

The shared `.glass-select-field` in `src/app/select.css` uses `flex: 1 1 180px`. When `.creator-filters` switches to `flex-direction: column` in `src/app/social.css`, that basis becomes a height rather than a width. Reset the mobile flex basis to `auto` and use `align-content: start`, or scope the 180 px basis to horizontal layouts.

## Deliberate behavior, not reported as defects

- Pantry matching and interactive likes/comments/follows remain preview/deferred features.
- English recipe names, ingredients, tags and descriptions on a Russian page are author content and intentionally are not auto-translated.
- Fixed bottom navigation appearing halfway down a full-page screenshot represents its position in the actual viewport; it is not by itself a page-layout defect. D01/D02 above are separately reproduced interaction problems.
- The auth backdrop covers the visible viewport, not the entire height of an expanded full-page screenshot. Scrolling within a short auth dialog is intentional.
- The simplified navigation, six editorial Home cards and absence of mock ratings follow approved requirements rather than the original reference image literally.
